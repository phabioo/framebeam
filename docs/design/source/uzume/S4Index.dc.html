Did not fit the design system
01OSD. Round 4’s top-centre OSD became Toasts at the bottom left of the stage, because GameStage allows no other overlay. Persistent ones (Paused, Rewinding) drop the ✕.
02Diagnostics. Resolved: F3 uses the GameStage diagnostics overlay, top right; hold Select uses its hotkey sheet.
03Panel tabs. Session · People · Chat · States became RunTabs Session · People · Chat · Saves (states live in Saves); in a run Run · Chat · Saves · plugin. Diagnostics left the tabs for F3.
04Plugin tab name. The plugin tab shows the run’s mode (SoulLink or Nuzlocke), set by SoulLink & Nuzlocke.
05Slider. Resolved: volume, voice and the Multiview mixer use Slider (mixer rows lead with the person square).
06Popovers. Resolved: volume, the bell and the map’s route card are Popovers (IconButton and MapPoint as anchors).
07Pause overlays. Pause, load-state and hold-Select use Dialog over a scrim on the stage only; RunHeader stays visible.
08Library tiles. Round 4’s tile grid became the Round 5 table. TableRow has no star, so favourites are a FilterChip and a Favourite button on the game page.
09Per-game sheet. Settings for this game was a sheet from the right; it is Dialog lg.
10Creature sprites. Placeholder boxes with two letters; the plugin draws real sprites from the game file. The old coloured icons and HP colours are gone; HP is a thin Progress.
11Region map. Drawn from route points and hairlines on stage; land comes from the game file and is not drawn.
12Speaking mark. Resolved: Avatar and MultiviewTile show speaking, mic off and muted by host (People tab 3g-12, Multiview).
13Pad keys. Resolved: R2, L2, R3 and the D-pad are GamepadHint keys. Round 4’s R1 / L1 became R / L; the plugin split moved to Select + ← because Select + ↓ is volume.
14Controllers. Mapping and gamepad options were not in the attached files; built from the AppNav item, the 7c pad map and the hotkey rules.
15Game data. Not in the files as a block; built from the map notes (read from the game file, stays on the PC) and placed in the plugin’s settings.
16Privacy rows. Resolved: a Privacy section in My account (8e-1, 8e-2) with two Toggles, off by default.
17Skipped. Resolved: the developer console is 4d-1 · 2. Hub web screens (3j-3, 6j, 6k, 5ah, 5gh, 7b) stay out; Uzume has no web admin.
18Stream view. 1920 × 1080 transparent overlay shown at 61 % on stage with a dashed frame.
Cheats · decisions
01Run for the rule. The rule is shown on Rally Night, a plain run on Harbor Rally started by Lena, so the run’s creator is a member, not the admin.New
02Where the setting lives. Settings › Server gets a Cheat database item after Updates (server-wide settings are in 3q; Systems & cores in 3l is a page, not a settings list). Without a server the same block is in Settings › This PC.New
03Safety copy. “Before cheats” is made each time the first cheat of a session goes on, not only at first use; consent itself is asked once per game.New
04Turning cheats off. The run’s confirm dialog is drawn for Off (it changes other people’s games); Allow has a lighter confirm in 11f-3.New
Cheats · did not fit the design system
01Code area. No multi-line field: a framed Mono box with line numbers; a bad line gets ✕, a danger tint and its own StatusIcon line, so it never relies on colour.
02Five panel tabs. RunTabs fits Session · People · Chat · Saves · Cheats only without the Chat count.
03Two actions in an empty state. StateBlock has one action, so the empty Cheats tab is a title, a sentence and two buttons.
04Disabled list. No disabled container: the blocked list is shown at 55 % with aria-disabled, under a notice that says why.
05One page per board. A board lives on one canvas page; 11e and 11f appear on sheet 3 as linked copies that follow the originals.
