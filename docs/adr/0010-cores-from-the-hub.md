# ADR 0010: Cores from the Hub (0.2)

- Status: accepted (Fabio, 2026-10-07, with the merge of the PR)
- Date: 2026-10-07
- Decided by: Fabio (proposal by the orchestrator; accepted with the PR)

## Context

Installers shipped the melonDS DS core. Milestone 0.2 ([Roadmap](../roadmap.md)) moves cores to the Hub, which distributes them to Players. The roadmap left the trusted source, index format, signing, offline Hub and license handling open. SHA-256 alone does not prove a trustworthy origin (`docs/architecture/05-emulation.md`). This ADR records the decisions; the wire contract is in [`protocol/README.md`](../../protocol/README.md).

## Decisions

### D1 Trusted source

- FrameBeam's own GitHub Releases: release `cores-index` holds `cores-index.json` and `cores-index.json.sig`; releases `core-<id>-<version>` hold the files.
- Default index URL `https://github.com/phabioo/framebeam/releases/download/cores-index/cores-index.json` (`--core-index-url`, env `FRAMEBEAM_HUB_CORE_INDEX_URL`).
- No admin upload (rejected by Fabio).

### D2 Signed index

- Index schema 1 (JSON): packages per (core id, version, platform) with license, source URL and ref, origin and files (name, role `library` or `license`, size, SHA-256, https URL). Unknown fields are ignored, an unknown schema is an error, invalid packages are skipped and reported, duplicate keys reject the whole index.
- Signature: Ed25519 over the exact bytes of the index, in `cores-index.json.sig` (`ed25519 <key_id> <base64>`). Integrity of each file comes from size and SHA-256 in the signed index, not from the URL host.
- Private key (seed) lives only in the GitHub secret `FRAMEBEAM_SIGNING_KEY`. The public key is compiled into the Hub (`corepkg.DefaultTrustedKeys`). The FrameBeam release key was generated by Fabio on 2026-10-07 (key `XNEQ9t7C…`).
- Extra keys: repeatable `--core-trust-key <base64 pubkey>` (env `FRAMEBEAM_HUB_CORE_TRUST_KEYS`, comma-separated). The admin owns the machine anyway; this enables forks, mirrors and the E2E test.
- Tooling: `server/cmd/framebeam-sign` (`keygen`, `add`, `sign`, `verify`, `pubkey`); the seed is read from the environment, never from a flag, and never printed.
- The updater in 0.3 reuses this key.

### D3 Package origin

- Windows x64: the upstream release asset with a pinned SHA-256, re-published as a FrameBeam release asset.
- Linux: built from the pinned source (`scripts/melonds-ds.pin`) in CI.
- Workflow `.github/workflows/cores.yml` (manual, and on pushes to `main` touching the pin) builds, publishes the release and the signed index.

### D4 Hub behavior

- Sync at startup (background, never blocks or fails startup), every 24 h and via "Check source now". Network failures leave the cache usable and are shown on the Systems & Cores page.
- The Hub downloads all platforms of the (core, version) selected by a system: its expected version, or for "any version" the highest listed version. Each file is checked for size and SHA-256 before it enters the cache.
- Index rows that are no longer listed are dropped together with their cache, unless the version is currently served.
- The Hub needs internet egress to github.com. Offline fallback: `framebeam-hub import-cores <dir>` (index, signature and files; same verification as sync; systemd: `packaging/linux/install-hub.sh import-cores <dir>`).
- Hub never runs cores. Handshake feature `cores_v1`.

### D5 Player trust and behavior

- The Player trusts the Hub (pinned TLS) and checks size and SHA-256 and the platform. It does not verify the signature; Player-side verification comes with the updater in 0.3 (moved to 0.4).
- Cache `<data>/cache/cores/<core-id>/<version>/<platform>/`, downloaded on demand before a game starts, loaded from there.
- A core version mismatch stays a warning (ADR 0007), until 0.7.
- Installers ship no cores.

### D6 Licenses

- The license text travels with each package as a `license` file; the index carries license, source URL and ref. melonDS DS is GPL-3.0.

## Rejected

- **Admin upload of cores:** rejected by Fabio; the admin would carry trust and provenance.
- **Bundling cores in installers:** keeps the installers large and ties core updates to Player releases.
- **libretro buildbot as direct source for Hubs:** unsigned and not pinned to a source revision. Revised on 2026-10-07 for 0.7 (Fabio): the buildbot may serve as the upstream for FrameBeam CI, which pins the SHA-256, signs and mirrors the files into FrameBeam's releases; Hubs still trust only FrameBeam's signed index (see `docs/roadmap.md`, 0.7).

## Consequences

- A fresh Player installation needs a Hub with a cached core before the first game starts.
- Until the release key exists, a stock Hub cannot verify the official index; admins can pass `--core-trust-key` or use `import-cores`.
- The Hub depends on GitHub availability for new cores only; cached cores keep working.
- Remaining open: Player-side signature check (implemented in 0.4, see below).

## Update 2026-10-07 (0.4)

D5: the Player-side signature check is implemented in 0.4 as specified in [ADR 0012](0012-internet-sessions-and-save-comfort.md) D6: the Player fetches the signed index from the Hub and verifies it on every `prepare()`; a failure marks the core "untrusted".
